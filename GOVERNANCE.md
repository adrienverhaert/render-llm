# Governance

Repository maintainers review contributions and approve releases. Issues record reproducible problems or bounded proposals;
pull requests connect the implementation to evidence and verification.

Changes to scene semantics, transport contracts and release prerequisites should
state compatibility effects before merging. The maintainer makes the final scope
and release decision after the applicable checks pass.

Use [CONTRIBUTING.md](CONTRIBUTING.md) for development and review expectations,
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) for participation, and
[SECURITY.md](SECURITY.md) for vulnerability reporting.

Stable/public binary distribution remains subject to the provenance and startup
requirements in [STATUS.md](docs/STATUS.md). A passing build is not a substitute
for runtime evidence or third-party redistribution obligations.
